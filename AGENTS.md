# Opcore

UPDATE THIS FILE when changing architecture, protocols, language coverage, cache identity, or verification conventions.

Opcore 0.3 replaces the legacy implementation in `the-open-engine/opcore` with the source snapshot developed in Opcore Zero. Keep `legacy` and existing release tags intact. The public npm package is `@the-open-engine-company/opcore`; executable/crate names, `.opcore.json`, `OPCORE_*` settings, provider identities, cache domains, and installation ownership use `opcore`. Do not adopt legacy or Zero hooks/receipts silently. Parser semantics and the pinned ASP definition remain unchanged by the product rename.

Release publication uploads the complete asset set to a draft before publishing the immutable GitHub Release. Never publish an empty immutable release and try to attach its assets afterward.

Opcore is one Rust package containing the pinned ASP definition, a private bundled-provider harness/composer, fast, Rust-native, Node-native, and Python-native ASP Core v1.0 `check` providers, the local verification CLI, and local dependency Sense. Providers produce assessments; conforming outer hosts own decisions, authority, assurance, receipts, and apply behavior.

## Product Boundary

- Default `opcore check` is the local CLI over the fast verification engine used by the default ASP provider. `check --providers fast,rust-native,node-native,python-native` explicitly selects private-harness processes; `all` selects the full set, and legacy `--native` remains fast plus Rust-native. `--comparison introduced|all` selects the ASP comparison explicitly. `--roots` treats each non-overlapping subfolder as a focus: fast uses the exact rebased focus, Node/Python retain the nearest applicable ancestor project configuration, and Rust retains repository context while selecting the focused Cargo package. Every provider run reports its focus, context, and elapsed time without writing the repository.
- Local `check --json` and `run --json` reports expose the selected configuration snapshot as `configuration.{state,view,digest,effective,origins}`; private provider-host Check reports retain their workflow selector alongside the same snapshot metadata. This is local CLI metadata only and never enters ASP assessments or `model::Assessment`.
- `src/api.rs` is the sole public crate boundary: executable entrypoints plus one hidden integration-test namespace. Implementation modules remain crate-private.
- `src/commands/workflows.rs` composes the existing Verify, Sense, and private provider evaluators with one selected configuration and a whole-run freshness check; keep workflow orchestration out of the evaluators. Pre-commit and CI default Verify/native to `all` but accept explicit `--comparison introduced`; Sense remains introduced-only and workflow coverage/native-authorization requirements are unchanged.
- `src/cli_args.rs` owns executable argument definitions and their help comments; the build-only `examples/cli-reference.rs` reuses them for the CLI reference. `scripts/build-docs.sh` assembles source-generated public rustdoc, all four `ProviderProfile` references, Markdown guides, and the pinned ASP definition into a link-checked static `target/site/`. CI builds docs on pull requests and tags and gates npm publication on that build. The build-only `scripts/docs_theme.py` and `scripts/docs/` assets share Zeroshot’s visual system across guides and rustdoc, with responsive navigation and a persisted light/dark preference; content and links remain usable without JavaScript. Keep documentation tools outside the runtime; do not duplicate command definitions or add a website framework or public implementation APIs merely to generate docs.
- Documentation publication keeps one archive per minor series at `vX.Y/`, updated only by a newer patch in that series, plus mutable `dev/`, a `stable/` redirect, `versions.json`, and per-snapshot identity/route manifests. `docs.yml` runs from main after successful CI or explicit recovery, verifies the exact source/tag, and stores the complete version tree on `gh-pages` before deploying Pages. `scripts/docs_versions.py` composes existing static builds without a framework, preserves release bytes on retries, records source and publisher commits separately, and keeps unversioned HTML links as redirects. A retry of the same release preserves its original bytes and source identity; a delayed older patch cannot replace newer documentation. Automatic publication keeps stable on the newest archived minor, including when older series receive backports. Run the publisher regression tests after versioning changes.
- Default local CLI checks block on findings or coverage gaps. An empty changed or staged selection is the distinct non-blocking `not_checked` outcome, not a clean assessment or a coverage gap; a selected project view with no supported source remains unsupported. `--advisory` makes findings report-only but never accepts missing coverage; manual Sense requires an explicit CLI or configuration acknowledgment for reported partial coverage. `--allow-node-builtins` accepts only explicit `node:` names in the pinned public built-in list and must continue rejecting unknown `node:` names, bare packages, unresolved local imports, aliases, dynamic references, parser gaps, and truncation. The installed post-write hook blocks on confirmed Sense findings or incomplete evaluation, but partial Sense coverage alone emits one concise hint and does not block by default; an explicit post-edit coverage setting can require intervention. The opt-in native harness emits its own local `allow`/`deny`/`indeterminate` decision but reports advisory assurance. That decision is not an ASP Core adoption receipt. Provider assessments never own either decision or assurance.
- One strict bounded root `.opcore.json` owns repository Verify/Sense thresholds, exact documentation bindings, target exclusions, native provider roots and selection, coverage acknowledgments, and the built-in `post-edit`, `pre-commit`, and `ci` workflows. Workflow fields override repository defaults once: objects merge by typed field, scalars and arrays replace, and an empty array clears an inherited list. Unknown/duplicate fields, null values, unsupported schema versions, symlinks, unsafe bounds, and unstable reads fail closed. No workflow inheritance, arbitrary commands, or executable configuration exists. Documentation ownership stays repository-wide; execution permissions and hard safety bounds remain host-owned.
- Configuration follows the selected source view: worktree, stage-0 index, or immutable target tree. Resolve effective settings once per workflow attempt and revalidate source, configuration, and retained native captures after rendering, retrying once. Individual `check` and `sense --workflow` commands apply workflow settings to their explicitly selected view. `run post-edit` checks worktree changes; `run pre-commit` checks the complete staged source with introduced Sense; `run ci --base <ref>` checks the complete target tree (HEAD by default) with Sense against the supplied immutable base. Full checks with no supported targets remain unsupported; empty changed selections remain `not_checked`.
- Target exclusions are normalized literal repository-relative file or subtree paths, matched on path-component boundaries before source reads and analysis bounds. Fast skips excluded source; Sense reports scope boundaries without claiming whole-repository graph coverage. Native provider roots select compiler projects/packages and retain required build context; reject exclusions that cannot be honored inside a selected native project rather than deleting compiler inputs or hiding compiler failures. All selected native checks are required and need explicit host execution authorization; post-edit never selects native execution.
- `status`, `doctor`, and `rules` are read-only operational surfaces. They must not evaluate source, build topology, create cache state, install anything, or mutate repository/agent configuration. Workflow inspection shows the selected configuration view, effective values, and origins; doctor treats selected native prerequisites as required. `rules --schema` emits the editor schema derived from configuration defaults and field metadata.
- Doctor may inspect bounded, receipt-owned Codex/Claude hook configuration. Distinguish absent integration, configured ownership, and incomplete or modified installation state; never infer host trust or live hook execution from files. A host-level smoke edit establishes activation.
- `opcore serve --stdio` selects the fast ASP provider; `--profile rust-native|node-native|python-native` selects one distinct native provider identity in the same executable.
- `asp/` is the complete ASP v1.0 definition maintained with Opcore: specifications, schemas, examples, decisions, governance/conformance material, and fixtures. `asp/SOURCE.json` records the immutable upstream starting point and, with its integrity test, binds the exact current definition; every published platform bundle includes this directory. Installed executables and absolute-path-bound manifests are runtime artifacts, not substitutes for or members of the protocol definition. Do not add the upstream reference host, manager/daemon, catalog, build system, or website merely to claim definition completeness.
- `opcore sense` is a separate local Git command. It derives an exact request-local file dependency graph and does not change the latency or protocol boundary of ASP `check`.
- MVP capability family: `check` only. Do not advertise `inspect` or `edit`.
- Supported language families: Node (JavaScript and TypeScript variants), Rust, Python, Go, HCL-based IaC (Terraform, OpenTofu, Terragrunt, and generic HCL), Shell (`sh` and Bash), and Protocol Buffers.
- HCL-based IaC uses pinned `hcl-edit` for native syntax and pinned `serde_json` for JSON forms. Check recognizes `.tf`, `.tofu`, `.tf.json`, `.tofu.json`, `.tfvars*`, Terraform/OpenTofu test files, `.terraform.lock.hcl`, exact Terragrunt filenames, and generic `.hcl`. Syntax and hygiene are covered; dependency, interface, callable, and token-region extraction remain explicitly unsupported.
- Shell uses pinned Shuck parsing. `.bash` defaults to Bash and ambiguous `.sh` defaults to the declared `sh` family; recognized Bash or `sh`/`dash` shebangs override the suffix default. The exact compile-target OS is part of the language mode, source-snapshot identity, file-fact identity, and diagnostic evidence, and analysis refuses a mode captured for another OS. Native OS shells remain authoritative: NEVER execute candidate scripts or infer host command availability/runtime behavior from syntax parsing. Shuck's POSIX dialect covers declared `sh`-family syntax but is not a complete POSIX portability proof.
- Go uses exact-pinned `tree-sitter-go` plus the matching Tree-sitter runtime for syntax, metrics, dependencies, interfaces, callable fingerprints, and token regions. `.go` and `_test.go` modes include the compile-target GOOS and GOARCH in language mode, snapshot identity, and file-fact identity. Standard filename and GOOS/GOARCH/`unix` build constraints are evaluated without a toolchain; custom, `cgo`, release, or compiler tags remain explicit partial coverage. Test files retain dependency facts but never contribute production exports. NEVER execute `go`, generators, compiler/linker tools, or repository code.
- Protocol Buffers uses exact-pinned `tree-sitter-proto` with the matching Tree-sitter runtime for bounded `.proto` syntax analysis. Syntax and hygiene are covered without invoking `protoc`; import resolution, interfaces, callable fingerprints, and token regions remain explicitly unsupported.
- Fast built-in checks own syntax, source hygiene, file size, function size, parameter count, nesting, and cyclomatic complexity.
- Node callable parameter counts and body boundaries come only from Oxc's parsed function, method, and arrow nodes; TypeScript type syntax must never be inferred as a runtime callable from token lookback.
- The fast provider, default Check, Sense, and installed hooks NEVER execute repository-controlled code, configs, plugins, build scripts, proc macros, lifecycle scripts, or repo-local binaries.
- The Rust-native provider is one explicit fixed Cargo Check backend. A repository-root run checks the full workspace; a selected Cargo package retains its outer captured workspace context and runs Cargo from that package without `--workspace`. It may execute build scripts, proc macros, wrappers, and build dependencies, which can read external/absolute path dependencies and host configuration or mutate scratch and any other OS-writable path. The bundled unsandboxed private harness is therefore trusted-repository/advisory use only and native execution is never enrolled in default Check or hooks. Authoritative or automatic native use requires an external host enforcing mount/filesystem, network, secret, descendant, CPU, and memory isolation.
- Rust-native success requires Cargo's structured successful `build-finished` message. For `introduced`, an absent baseline project is the empty before-set, while a failing baseline is incomplete because compiler short-circuiting cannot establish an exhaustive before-set.
- Node-native is one fixed locked TypeScript backend: root `package.json`, root npm lock, and exact `tsconfig.json` or `tsconfig.*.json` projects only. It runs `npm ci` offline with lifecycle scripts/audit/funding/update checks disabled in private scratch, invokes only the installed root project-local `tsc` with no emit or incremental state plus `--listFiles`, then removes generated `node_modules` before immutable-materialization verification. The union of compiler file lists is its exact semantic universe. Config-admitted JavaScript/TypeScript is checked; files outside every project remain fast-provider syntax/hygiene territory and are counted without invalidating configured-project coverage. It never invokes package scripts, ESLint, arbitrary plugins, or a repository-selected command. Missing offline dependencies or `tsc` are unavailable coverage, not clean.
- Python-native is one fixed type-checking backend: host Pyright preferred, host mypy fallback. The private harness selects an explicit `OPCORE_PYTHON`, the nearest project-context `.venv`, or an active project-contained `VIRTUAL_ENV`, in that order; direct ASP use otherwise records an ambient PATH interpreter. The provider passes that interpreter to Pyright/mypy, hashes and revalidates it plus any adjacent `pyvenv.cfg`, and passes every exact selected `.py`/`.pyi` path to the checker. It requires Pyright's structured `filesAnalyzed` count to cover that explicit set or accepts strictly parsed mypy output with an ephemeral cache; it never creates, synchronizes, or mutates a Python environment. Unresolved imports from an ambient interpreter make coverage incomplete instead of becoming authoritative project findings. Missing tools, dependencies, malformed output, or unsupported failures remain unavailable/incomplete. Mypy configuration may load repository plugins, and the selected Python environment may contain executable checker/plugin code, so all native profiles share the trusted-repository/external-sandbox requirement.
- Graph assembly, comparisons, and observations stay outside fast Verify. They must not add workspace enumeration, topology state, or graph policy to the default `check` request path.
- Sense may persist only bounded, versioned, path-independent, content-addressed dependency, interface, callable-fingerprint, and exact token-region facts through the existing shared cache. NEVER persist resolved edges, topology, snapshot comparisons, duplicate groups, documentation bindings, dirty views, or a mutable current graph.
- Sense resolves only uniquely confirmed local file dependencies. Node runtime and type-only edges remain distinct; Python support is explicit-relative imports only. Rust emits structural `mod`/`use`/`pub use` edges only for module files proven reachable from conventional `src/lib.rs`, `src/main.rs`, or `src/bin/*/main.rs` roots. Structural edges feed dependency limits, impact, and importance but NEVER runtime-cycle findings. Go resolves exact imports inside the deepest enclosing root or nested `go.mod` module, aggregates production files by package directory onto one deterministic representative, and keeps test files separate. Go package imports are runtime edges; external modules, `go.work`, `replace`, vendor/GOPATH context, and malformed or unavailable relevant module metadata are never guessed. Cargo-configured roots, cfg/cfg_attr, `#[path]`, macro-generated modules, unknown bare-path aliases, and undeclared files remain explicit partial coverage.
- Blocking Sense rules are introduced runtime dependency cycles, exact nontrivial duplication, explicit module/edge/interface limits, and exact documentation obligations for mechanically important modules. Every rule is introduced-only; unchanged or reduced baseline debt never blocks. An empty comparison may retain `partial` status and baseline coverage evidence but exits successfully without `--allow-partial`; incomplete evaluation still blocks. Fan-out deltas and reverse impact remain observations.
- Documentation ownership uses only `.opcore.json`'s `documentation.bindings` exact source-to-document registry. NEVER infer ownership from basenames, prose substrings, global Markdown search, globs, or regexes. Configuration and referenced documents are captured and revalidated in the same selected source view; they are never persisted as shared facts. The unified file is bounded to 256 KiB and 4096 documentation bindings. Paths are literal Git paths; no pattern syntax exists. The former separate registry is not read; this unpublished v1 definition has no migration layer.
- Documentation enforcement reports binding-specific partial coverage when a changed, important, bound Python module lacks authoritative public surfaces in either view, because `sense.documentation.document_not_updated` cannot be evaluated. Exact static module-level `__all__` remains authoritative; do not infer Python functions or classes into export limits or importance.
- Sense JSON exposes one `effectivePolicy` object for cycle-adjacent thresholds, exact-duplication minima, interface limits, importance, and the documentation registry path; do not split overlapping policy truth across category-specific output objects.
- Do not add graph ASP capabilities, topology databases, daemons, watchers, FTS, symbol/call graphs, centrality, semantic clone search, generic plugin/tool execution, or another native backend beyond the fixed Rust/Node/Python set without a new architecture decision.

## Robustness Rules

- ALWAYS identify local repositories through the canonical Git common directory and snapshots through Git tree/blob identities plus overlay digests.
- Resolve Git's relative common-directory and index paths against the invocation directory, including normal-clone subdirectories. Skip hooks only for a confirmed non-repository; missing Git, corrupt metadata, and other discovery failures remain blocking infrastructure failures.
- NEVER key correctness to worktree paths, mtimes, cache age, or a mutable "current graph".
- Local Git capture MAY include inode and timestamp generation metadata only to detect concurrent mutation and ABA rewrites; content identities remain authoritative for facts and assessments.
- ALWAYS resolve explicit Check `--base` and `--tree` refs to immutable tree IDs before capture and resolve them again during post-evaluation freshness validation. `--tree` reads only Git objects; explicit-base worktree and index checks compare exact current content to the resolved base without mutating Git state. Unborn repositories use Git's object-format-specific empty tree as the default staged/changed baseline.
- ALWAYS revalidate a local Git capture after evaluation and output rendering, retrying once before returning an assessment.
- Native host capture is separate from `SourceSnapshot` and provider-aware. Fast captures recognized source; Node captures JS/TS plus bounded JSON/package/npm context; Python captures `.py`/`.pyi` plus fixed checker-config names. Rust first discovers exact focus applicability and, when applicable, captures a fixed repository-wide Cargo build-input envelope even for a focused package: Rust/Cargo controls, native build sources, schema/codegen inputs, common textual compile resources, and exact license notices. This keeps workspace/path dependencies and ordinary literal `include_*` resources while excluding arbitrary media, archives, datasets, and opaque binary payloads that cannot be inferred safely; a build that actually requires an omitted input must remain unavailable/incomplete rather than widening capture dynamically. Provider and focus/context filtering happen during Git path discovery before file-count/byte bounds and content reads. Capture reads tracked and non-ignored untracked regular files in that envelope, ignores directory, Gitlink, and symlink entries, caps each selected file at 4 MiB and the selected request at 10,000 files/256 MiB, shares unchanged before/after bytes, and revalidates HEAD, linked-worktree index, exact selected path set, content, and generations. A selected tracked regular file replaced by a non-regular worktree entry still fails closed. Worktree mode compares HEAD to current bytes; staged mode compares HEAD to stage 0 and ignores unstaged/untracked bytes. Never imply capture or scratch confines external dependencies, tool/cache homes, wrappers, plugins, or toolchain files.
- Sense workspace capture reads dependency-source-candidate HEAD paths plus exact relevant `go.mod` metadata once, then overlays only Git-status paths plus skip-worktree and assume-unchanged paths. `src/source/languages.rs` owns the shared recognized-code envelope for Check/ASP and Sense plus the separate Sense-only metadata capture envelope; unknown docs/data stay outside coverage. Capture must retain staged deletions, read missing sparse paths from stage 0, count recognized unsupported code honestly, derive supported changes from captured bytes, and revalidate HEAD, index, overlay content, and overlay generations; identical-content metadata churn does not make a different content view.
- Keep Git path-set selection in `src/source/git/paths.rs`; `src/source/git.rs` owns shared capture/plumbing, while workspace and auxiliary view behavior stays in their existing submodules.
- `sense --staged` MUST compare the full dependency-source and selected Go-module HEAD tree with the full stage-0 index, ignore unstaged and untracked worktree bytes, and revalidate the linked-worktree-local index plus HEAD. Go module metadata, documentation registry, and referenced documents MUST use the same selected source mode. Staged capture never writes a tree, stash, temporary worktree, or repository state.
- `sense --hypothetical` MUST use one exact current-worktree capture as before and apply one strict bounded write/delete request to supported source, selected Go module metadata, and selected documentation inputs in memory. Bind the request digest into freshness, revalidate the untouched base worktree after evaluation, allow unified configuration overlays only when documentation bindings change and every other repository/workflow setting stays identical, and never write candidate files, index/tree objects, stashes, temporary repositories, or persistent topology.
- Exact auxiliary capture is caller-selected and request-local. It reads baseline HEAD and the current worktree with stage-0 fallback for missing skip-worktree paths, never follows symlinks, and revalidates the worktree-local index plus selected path bytes and generations. It is capped at 4097 paths, 4 MiB per file, and 32 MiB independently per before/after view; unchanged content shares storage. Do not persist auxiliary snapshots or use them to widen ordinary source coverage.
- The shared parser worker pool is capped at four threads per process - WHY: simultaneous worktree gates must not multiply a 16-core host into 128 parser workers or create allocator high-water spikes. Profile any change to this cap, but do not make elapsed time or RSS a release threshold.
- Language entry modules orchestrate parsing only: Node structural preflight and metrics live under `src/analysis/node/`, Rust callable metrics live under `src/analysis/rust/`, and Go input, metrics, interfaces, and iterative walking live under `src/analysis/go/`.
- HCL, Shell, and Protocol Buffers run bounded structural preflights before their parsers. Their syntax analyzers return unsupported dependency, interface, callable, and token-region facts so Sense can report partial coverage without guessing edges.
- Node module-kind resolution uses exact colon-delimited language-mode components. NEVER match `script`, `module`, or `commonjs` as substrings: the `javascript` and `typescript` family names must remain unambiguous so Oxc can recognize ESM syntax.
- Git repository discovery/capture stays in `src/source/git.rs`; Git command/object transport lives in `src/source/git/objects.rs`, no-follow worktree content/state lives in `src/source/git/state.rs`, and the raw native view stays in `src/source/git/native.rs`.
- ASP lifecycle and request normalization stay in `src/protocol/asp.rs`; fast/native workspace materialization and assessment conversion live in the corresponding `src/protocol/asp/` child modules. The minimal blocking host transport stays in `src/protocol/host.rs`; local selection, focus/context projection, composition, and decision policy stay in `src/protocol/host_cli.rs`; bounded native execution and output parsing stay under `src/protocol/native.rs`.
- Bundled provider identities and source documentation live in `src/protocol/asp/profile.rs`, reexported through the existing ASP and public API boundaries.
- ALWAYS read ASP candidate content through host `workspace/listTree` and `workspace/readBlob` callbacks within the initialized grant.
- ALWAYS materialize fast Git and ASP inputs into the concrete immutable `SourceSnapshot` before evaluation; the fast engine must not perform hidden source I/O or depend on transport-specific views. Native ASP content is instead materialized into a provider-private temporary tree because native tools require non-source inputs. Place provider and native scratch under a fixed host temporary base outside the candidate repository, never an ambient candidate-controlled temp path. ASP v1.0 callbacks do not carry executable or other file modes, so create every callback file as a regular owner-read/write file (`0600`) and keep mode-sensitive builds explicitly outside these profiles. Opcore never intentionally points a native tool at the user's candidate worktree, but the temporary copy is mutable execution scratch and does not confine what tool or repository-controlled code may access. Derive diagnostic semantic keys only from immutable callback bytes, never by rereading post-execution scratch.
- ALWAYS keep the ASP ChangeSet digest, content snapshot identity, blob read set, and file-fact key distinct.
- Content snapshot identity includes each path, language, language mode, and content identity. Language suffix recognition is owned once by source discovery and reused by request-local resolution.
- ALWAYS bind assessments to the exact baseline, ASP ChangeSet digest, blobs read, effective config digest, provider build digest, and capability version.
- Rust-native runs only `cargo check --workspace --all-targets --message-format=json` for a full root or `cargo check --all-targets --message-format=json` from an explicitly focused Cargo package, adding `--locked` when the captured Cargo context has a root `Cargo.lock`. It inherits only an explicit set of variables needed to locate host Cargo/Rustup/toolchain/cache state, overrides all temporary-directory variables with its fresh private target directory, forces Cargo offline and nonincremental, bounds combined output and cumulative wall time, and observes cancellation. Cargo and the PATH-selected rustc launcher identities are hashed under bounds and revalidated after execution. The environment is narrower, not sanitized or secret-free; offline mode is not enforced network denial; fresh target/disabled assessment caching does not prevent Cargo from reading or mutating its ambient homes. These are execution-hygiene controls, not a sandbox, and the native manifest must declare potential writes to those ambient Cargo/Rustup stores.
- Node-native runs only fixed offline `npm ci` and project-local `tsc --project <exact-tsconfig> --noEmit --pretty false --listFiles --incremental false` commands. It inherits only the declared Node/npm environment, bounds all subprocesses cumulatively, hashes and revalidates npm, the PATH-selected Node runtime, and the materialized project-local `tsc`, rejects tracked `node_modules`, records configured and unconfigured JavaScript/TypeScript counts, and removes every generated dependency tree before verification. Its npm cache may be read/written; it never claims offline mode is network enforcement.
- Python-native runs only host Pyright `--outputjson --warnings --threads 1 --pythonpath <selected-interpreter> <exact-source-paths...>` or fixed host mypy flags including `--python-executable <selected-interpreter>` plus those paths with a provider-private cache. It inherits only the declared checker/Python environment, does not install dependencies, and requires structured/count-consistent Pyright output with sufficient `filesAnalyzed` coverage or recognized mypy diagnostics. Checker, interpreter, and adjacent environment-marker identities are revalidated after execution. Ambient unresolved-import diagnostics make coverage incomplete; project-selected environment diagnostics remain findings.
- After native execution, revalidate the materialized root directory identity, boundedly re-enumerate scratch, and require every callback file to remain regular and byte-identical. Reject removals and unexpected entries. Rust alone may leave a newly generated root `Cargo.lock` when absent from callbacks, and hashes it into evidence; Node/Python permit no new entry. Treat this as detection of residual scratch mutation, never as containment or proof that transient, restored, or external writes did not occur.
- ALWAYS make cache entries content-addressed and versioned. Writes use a same-filesystem temporary file and atomic publication; corrupt entries are misses and are repaired on the next write. Do not fsync disposable facts.
- ALWAYS validate cache roots before creating them, amortize allocated-byte quota scans under a process-released shard lock, publish facts no-clobber, and let ordinary cache I/O failure degrade to an uncached evaluation. Only unequal payloads for one deterministic fact key are authoritative failures.
- ALWAYS bump `analysis::FACT_ABI` when parser, metric, or diagnostic fact semantics change so installed upgrades cannot reuse stale facts.
- Exported TypeScript interface/type-literal and Go struct/interface facts include bounded, whitespace-insensitive token fingerprints - WHY: documentation enforcement must observe same-size member/signature changes without persisting paths or building a symbol graph.
- ALWAYS keep persisted dependency, interface, callable-fingerprint, and token-region facts path-independent and bounded. Resolution, duplicate grouping, and policy belong to the exact request snapshot because identical content at different paths can resolve or compare differently.
- ALWAYS rebuild the request-local Rust module index when Rust content changes, prove module reachability from a supported conventional root before resolving edges, and keep compile-time structural edges distinct from runtime and type-only edges - WHY: arbitrary `.rs` files may be custom crate roots, undeclared files are not modules, and reciprocal Rust `use` relationships are valid rather than runtime-cycle defects.
- ALWAYS rebuild the request-local Go package/module index when Go source or relevant `go.mod` bytes change. Select the deepest enclosing module, resolve only exact module-prefix package directories, aggregate production interfaces on one deterministic package representative, and bind module bytes into graph view identity and freshness. NEVER persist `go.mod`, resolved Go edges, or package topology, and never interpret `go.work`, `replace`, vendor, GOPATH, or executable project configuration.
- Callable fingerprints MUST be produced during the existing language parser/token pass, use language-family-separated domains, preserve syntax-significant structural tokens, Node inter-token line breaks, and Go semicolon-insertion line boundaries, omit nested callables from an enclosing callable, and stop at 4,096 callables per file. Request comparison stops at 200,000 callable occurrences. Either bound yields explicit incomplete coverage with a stage-specific code, fixed limit, processed count, before/after view, bounded deterministic affected-path sample, sample-truncation marker, and honest recovery note.
- Token-region facts MUST be produced during that same parser/token pass. Use 32-token rolling k-grams with a 17-k-gram rightmost-minimum winnowing span, retain at most 4,096 anchors per file and 200,000 per request, and preserve compact exact token-span evidence for confirmation. Anchor hashes nominate candidates only: request-local comparison MUST exact-check normalized tokens, extend maximal regions, prefer the region supported by the most occurrences, retain language domains and one-to-one path continuity, and stop at 4,000,000 token comparisons. Any bound or malformed exact evidence yields explicit incomplete coverage; resource-limit issues carry the same stage/limit/count/view/path contract as callable limits, while malformed evidence retains a distinct fail-closed fallback. Never emit partial per-file facts or expand occurrence pairs.
- Counted token-region evidence records MUST cover at least one source byte. Zero-width structural markers, such as Python dedents or synthetic line boundaries, are uncounted prefix components and never standalone records.
- `src/sense/dedup/regions/evidence.rs` owns bounded exact token-evidence decoding; request-local region views share each decoded fact by its content-addressed fact key.
- ALWAYS project interface facts only for changed-module policy paths, including exact-continuity paths, while retaining the full request-local dependency projection for confirmed fan-in. Wildcard, namespace-width, unsupported public-surface, parser-failed, and truncated evidence must never become authoritative before widths.
- ALWAYS compare Sense before/after graphs with one-to-one exact-content path continuity so pure renames do not become fabricated graph regressions.
- ALWAYS report dependency and interface extraction/resolution coverage by semantic kind. `src/sense/resolver/classification.rs` owns reference classes, `src/sense/resolver/evidence.rs` owns bounded evidence sampling, and `src/sense/resolver/node.rs` owns the pinned public Node built-in list. Each graph view includes at most five deterministic path/specifier/kind resolution-gap samples and an explicit sample-truncated marker. Ambiguous, config-dependent, dynamic, parser-failed, wildcard, namespace-width, unsupported public-surface, or truncated inputs never become guessed facts or a global clean-completeness claim.
- ALWAYS use iterative, bounded graph algorithms and deterministic path/edge/output ordering. Graph work must remain O(V+E), including adversarial depth; exact-duplicate grouping must remain linear apart from ordered-index logarithmic factors and never expand into occurrence pairs.
- Opcore itself MUST NEVER write the user's candidate source tree or Git state. Native providers write only private materialization/output/cache paths they allocate, except npm may use its explicitly inherited cache; without external mount confinement executed code can still mutate any host-writable location. Local fast/Sense cache writes go only to the configured cache root.
- ALWAYS bound input bytes, file count, line length, process count, tool runtime, output bytes, and JSON-RPC frame size.
- All Git process stdout/stderr is read concurrently under explicit byte caps. Scoped tree, index, and sparse-path reads stay path-batched and never fall back to whole-repository output.
- ALWAYS reject excessive delimiter, indentation, unary, binary, and postfix expression depth before invoking recursive parsers or AST walkers. Nested Rust block operands must preserve the enclosing expression-chain budget.
- ALWAYS fail closed for malformed protocol data, unavailable required rules, stale identities, callback refusal, timeouts, crashes, and truncated required coverage.
- Python syntax, metric, dependency, interface, callable-fingerprint, and token-region facts use the exact pinned Ruff parser/AST crates. Keep the pre-parser structural pass token-based and bounded, then traverse the parsed AST by reference; do not add unmaintained parser subtrees or copy ASTs merely to inspect them.

## ASP Rules

- Implement JSON-RPC 2.0 newline-delimited stdio with `initialize`, `initialized`, `check/evaluate`, `$/cancelRequest`, `shutdown`, and `exit`.
- Keep fast, Rust-native, Node-native, and Python-native as distinct process identities and manifests even though one binary implements all profiles. The private local harness launches each through the same lifecycle/callback boundary; it does not call provider internals as a privileged fast path.
- Reject capability work before the initialized grant.
- Request read-only, no-network permissions and obey the narrowed host grant. Offline flags alone cannot enforce that grant on native descendants; authoritative native execution requires the external host sandbox described above.
- Advertise `check/1.0` and comparisons `introduced` and `all`. Fast advertises `changeset` and `workspace` scopes and accepts path subsets without advertising a third scope; every native profile advertises workspace only.
- Advertise exact capability fields: source namespace, scopes, comparisons, `partialResults:false`, `incremental:false`, `unsupportedReporting:"assessment-status"`, and `fixes:false`.
- Accept only the canonical `check/evaluate` request. Reject private host compatibility shapes. Fully validate canonical `priorDiagnostics` and `priorAssessments`, including optional-field nullability and nested provider-data prohibitions, but do not act on them while advertising `incremental:false`.
- `check/evaluate.configuration` carries only normalized provider settings. Fast validates its `verify` thresholds through the shared configuration validator; native profiles currently accept an empty settings object and read compiler configuration through callbacks. Omission means documented defaults. Providers bind effective settings and profile identity through the existing stable `configDigest`, which the host verifies for every result status. Timing and execution evidence must not enter configuration identity. Workflow names, override resolution, target filtering, and host decisions stay outside provider settings.
- Treat the host as the read-grant authority. Request exact paths or the workspace through callbacks and preserve typed host refusal; do not implement a second glob language in the provider.
- Read blobs in individually frame-bounded callbacks; a full native workspace must not require one oversized JSON-RPC response.
- Treat callback success-shape violations, contradictory blob identities, and content/digest mismatches as contract failures while preserving typed callback errors from the host. Ignore directory entries, report source symlinks as unsupported, and report truncated required listings as incomplete assessment coverage.
- Implement ASP `introduced` as set difference by public diagnostic fingerprint: if a fingerprint occurs anywhere in the before-set, no after occurrence of that fingerprint is introduced.
- Provider output must never contain host-owned decision, verdict, pass, disposition, receipt, authority, assurance, policy, transaction, or apply-result fields, including nested data.
- NEVER describe the private bundled-provider harness as a conforming ASP Core outer host or adoption-evidence implementation. It has no `host/status`, `host/capabilities`, or `host/evaluateChangeset` surface, discovery/enrollment, policy authority registry, host receipt, apply, daemon, or OS sandbox/mount confinement. Its process-group sweep is best-effort cleanup only. It must label its actual advisory assurance and reject stale, malformed, misattributed, or host-field-bearing assessments before composing its private local decision.
- Use `unsupported-version` for protocol negotiation failures and `provider-not-initialized` for capability work before the initialized grant. Assessment evidence records the exact narrowed initialized grant used for callbacks.
- Any `exit` notification terminates the stdio process; only `shutdown` followed by `exit` is a clean lifecycle.
- Artifact checksums provide integrity only. They never grant trust, certification, registry status, or gate authority. Do not invent ASP certificate or signature semantics.
