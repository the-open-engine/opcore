Opcore 0.2.2 fixes validation for repositories where the workspace root sits below the Git worktree root.

Scoping Opcore to a nested package inside a monorepo, with `--repo packages/app` or an equivalent
configuration, produced workspace-relative paths where Git object reads and diff listings needed paths
relative to the worktree root. Base-tree and staged reads failed outright, so the run ended in
`infrastructure_failure` with no checks executed. Every scope that reads committed content was affected.

This release:

- resolves the Git prefix for a workspace rooted below the worktree root;
- keeps changed, staged, tree, tracked, and untracked listings scoped to that workspace;
- translates workspace-relative file reads back to worktree-root-relative object paths; and
- adds regression coverage for nested base-tree reads, sibling-package exclusion, and workspace-relative
  file inventories.

Repositories whose workspace root already matches the worktree root behave exactly as before.

Reported and fixed by Sigurd Høystad (@saasom) in #298.

Install:

```sh
npm install --global opcore@0.2.2
```

Or run without installing:

```sh
npx opcore@0.2.2 --version
```
